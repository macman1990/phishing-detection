# بنك أسئلة متوقعة لمناقشة PhishGuard

الإجابات أدناه مرتبطة بما يظهر في الملفات التي تمت مراجعتها. أي قرار تاريخي للفريق أو معلومة تشغيل غير موثقة ذُكر صراحة أنه يحتاج تأكيدًا.

## الفكرة والأهداف

### 1. ما المشكلة التي يعالجها المشروع؟

يساعد على جمع مؤشرات البريد والروابط في تقرير triage واحد: بيانات المرسل، نتائج المصادقة الموجودة في الرسالة، محتوى البريد، URL، معلومات التهديد، ودرجة نموذج ML. لا يحل محل محلل أمني ولا يضمن اكتشاف كل رسائل التصيد.

### 2. من المستخدم المستهدف؟

تسميات SOC وBlue Team في الواجهة وREADME تشير إلى محلل SOC أو مستخدم تعليمي/بحثي. لا توجد في الكود إدارة مستخدمين أو صلاحيات أو دعم متعدد المستأجرين.

### 3. هل النظام يحظر البريد أو يعزل المرفق تلقائيًا؟

لا. الواجهة تعرض توصيات نصية وتحفظ تنبيهًا، لكنها لا تتصل ببوابة بريد لتنفيذ الحظر أو العزل.

### 4. ما الفرق بين نتيجة الأداة والحكم النهائي؟

النتيجة score وverdict مبنيان على قواعد ومصادر وموديل. هي مؤشر للمراجعة، وليست إثباتًا جنائيًا أو تأكيدًا بأن الرابط آمن/ضار.

## التصميم والمعمارية

### 5. ما نقطة الدخول الأساسية؟

لواجهة المستخدم: `main.py` عبر `streamlit run main.py`. لمحرك البريد: `modules/risk_engine.py` ويمكن تشغيله كـCLI، مع ملاحظة أن هذا المسار ينفذ اتصالات خارجية.

### 6. كيف يمر البريد داخل النظام؟

`email_parser` يقرأ EML، ثم `header_checker` و`content_analyzer` و`url_analyzer` و`threat_intel` و`advanced_analyzer` و`ml_classifier` تنتج مؤشرات. `risk_engine` يدمجها في درجات وحكم وflags، ثم الواجهة تحفظ alert ويمكنها إنشاء PDF.

### 7. هل يوجد Backend منفصل؟

لا يظهر Backend مستقل أو API server. تطبيق Streamlit يستدعي وحدات Python مباشرة داخل عملية التطبيق.

### 8. هل يستخدم المشروع قاعدة بيانات؟

لا يظهر SQLite في التنفيذ. التنبيهات JSON Lines، وبيانات التدريب CSV، ومقاييس التحقق JSON، والنموذج pickle، والتقرير PDF.

### 9. ما الأوزان المستخدمة؟

في `risk_engine.py`: Header/Auth 22%، Content 18%، URL rules 18%، VirusTotal 14%، URLhaus 8%، ML 10%، Advanced 10%. مجموعها 100%. `config.py` يحتوي قاموسًا أقدم غير مطابق، ولذلك يلزم توحيده في تطوير لاحق.

### 10. كيف تُحدد مستويات الخطورة؟

`CRITICAL` من 75، و`HIGH` من 50، و`MEDIUM` من 25، وما دون 25 `LOW`.

### 11. هل فحص SPF/DKIM/DMARC يتم مباشرة من DNS؟

لا يظهر في الكود استعلام DNS لتلك البروتوكولات. `email_parser` يستخرج قيمًا من ترويسة `Authentication-Results` في الرسالة، ثم `header_checker` يقيّمها.

### 12. كيف يعمل فحص URL المستقل؟

تعمل قواعد `url_analyzer` محليًا، ثم يستعلم `full_url_check` VirusTotal وURLhaus وPhishTank وGoogle Safe Browsing. الدرجة المجمعة هي متوسط درجات المصادر الأربعة؛ درجة Rule Engine تظهر منفصلة ولا تدخل في المتوسط.

## الكود والموديولات

### 13. ما دور `email_parser.py`؟

قراءة بايتات EML باستخدام `eml-parser` واستخراج sender وreply-to وsubject وdate وrecipients وURLs وبيانات attachments وauth results ونص الرسالة.

### 14. هل يفحص النظام محتوى المرفقات؟

لا يفحص بايتات الملف بحثًا عن malware ولا يشغله. يفحص metadata مثل الامتداد والحجم واسم الملف، وبعض قواعد المحتوى ترصد امتدادات خطرة. الهاشات المستخرجة بيانات تعريفية وليست تحليلًا للمحتوى.

### 15. كيف يستخدم المشروع نموذج ML؟

`ml_classifier.extract_features` يبني عشر ميزات من تقرير البريد، منها طول URL ووجود IP وHTTPS والكلمات المشبوهة ونتائج المصادقة ودرجة VT. `RandomForestClassifier` يتنبأ ويحسب احتمالية phishing. يعتمد استخراج URL أساسًا على أول رابط.

### 16. ماذا يحدث إذا لم يوجد `data/model.pkl`؟

`load_model` يحاول تشغيل `train_model` من `data/dataset.csv` ويحفظ نموذجًا محليًا. لكن `data/validation.py` نفسه يفتح الملف مباشرة، لذلك يحتاج إنشاء النموذج قبل تشغيل validation.

### 17. هل `python -m modules.ml_classifier` يدرب فقط؟

لا. عند تشغيل الملف كبرنامج، ينفذ تدريبًا ثم يستدعي تحليل `data/test.eml`، وهذا يعني اتصالات الشبكة في مسار تحليل البريد. لتدريب النموذج فقط استخدم:

```powershell
.\venv\Scripts\python.exe -c "from modules.ml_classifier import train_model; train_model()"
```

### 18. ما مخرجات التنبيه؟

`siem_integration` ينشئ JSON alert ويحفظه كسطر في `reports/siem_alerts.log`، ثم يحاول إرسال datagram عبر UDP إلى المضيف والمنفذ المحددين. `sendto` الناجح لا يؤكد وصول الرسالة أو معالجتها.

### 19. هل هناك تكامل مثبت مع Wazuh أو Splunk أو ELK؟

الموجود في الشيفرة إرسال UDP JSON عام فقط. لا توجد ملفات إعداد أو قواعد أو اختبارات تثبت التوافق الفعلي مع منتج بعينه؛ لذلك لا يصح وصف التكامل بأنه مجرب أو مكتمل.

### 20. كيف يُنشأ PDF؟

عند طلب المستخدم في الواجهة، تستدعي `report_generator.generate_report` مكتبة ReportLab وتكتب افتراضيًا `reports/incident_report.pdf`، ثم توفر الواجهة تنزيلًا باسم alert. لا ينشأ التقرير تلقائيًا مع كل تشغيل.

## المكتبات والاختيارات

### 21. لماذا Streamlit؟

Streamlit مستخدم فعليًا لبناء لوحة تفاعلية مباشرة من Python. لا يوجد توثيق يثبت مقارنة تاريخية مع Flask أو Django أو React، لذلك لا يمكن الجزم بأن مقارنة رسمية حدثت.

### 22. لماذا scikit-learn؟

الكود يستخدم API جاهزًا لـRandom Forest وtrain/test split وcross-validation ومقاييس التصنيف. سبب الاختيار التاريخي غير موثق؛ هذه إجابة مبنية على الاستخدام الظاهر فقط.

### 23. ما استخدام pandas وNumPy؟

pandas يقرأ CSV ويبني جداول الميزات؛ NumPy يظهر في إنشاء بيانات إضافية وحساب بعض المقاييس والتحويلات.

### 24. ما استخدام BeautifulSoup؟

تحليل HTML في محتوى البريد لاكتشاف عناصر مثل forms وحقول hidden وصور خارجية، وليس تشغيل صفحة ويب.

### 25. هل WHOIS إلزامي؟

لا. `advanced_analyzer.py` يحاول استيراد `whois` داخل `try/except`، وعند غيابه يجعل هذه القدرة غير متاحة. الحزمة الاختيارية `python-whois` غير مدرجة في `requirements.txt`.

### 26. لماذا لا يستخدم SQLite؟

لا يوجد دليل في الكود على استخدام SQLite. التخزين الحالي ملفات محلية بسيطة. سبب عدم اختيار قاعدة بيانات غير موثق، ويمكن تفسير ذلك بأنه يلائم نموذج المشروع الحالي، لكن لا ينبغي عرضه كقرار رسمي للفريق.

## الاختبارات والنتائج

### 27. هل توجد اختبارات وحدات؟

لا توجد مجلدات أو ملفات unit-test واضحة في قائمة Git. يوجد `data/validation.py` لتقييم النموذج وكتابة JSON metrics، لكنه ليس اختبارًا آليًا لواجهات الموديولات.

### 28. ما الأرقام المسجلة؟

الملف الحالي يعرض dataset_size 99,004، accuracy 0.880، precision 0.871، recall 0.801، F1 0.834، AUC-ROC 0.941، false-positive rate 0.073، ومتوسط latency 3.988ms. هذه لقطة محفوظة، ولم يُعَد تشغيلها أثناء مراجعة الوثائق.

### 29. هل المقاييس كلها من نفس تجربة التقييم؟

الكود يحسب متوسط accuracy عبر 5-fold cross-validation، ثم يحسب precision وrecall وF1 وAUC وFPR من تقسيم 70/30 منفصل. لذلك لا ينبغي تفسير كل الحقول على أنها خرجت من تقسيم واحد. ملف JSON لا يحتوي تاريخًا أو بصمة للبيانات والنموذج.

### 30. هل دقة 88% تضمن اكتشاف رسالة جديدة؟

لا. المقاييس تتعلق ببيانات وتقييم محفوظين، ولا تثبت الأداء على عينات مستقبلية أو بيانات مختلفة. يلزم معرفة مصدر البيانات، اختبار مستقل، ومراجعة false positives/false negatives.

### 31. هل أُعيد تشغيل الاختبارات في هذه المراجعة؟

لم يُشغّل model validation أو APIs أو التطبيق أثناء مرحلة التوثيق. تم تحليل ملفات Python نحويًا وقراءة JSON الموجود. ينبغي على الفريق تشغيل تجربة معزولة، وحفظ نتائجها وتاريخها قبل العرض النهائي.

## الأمان والخصوصية

### 32. هل الروابط تُزار مباشرة؟

في مسار البريد، نعم: `advanced_analyzer.analyze_redirect_chain` يستخدم `requests.get` ويتبع redirects لأول URL ويحدد `verify=False`. أما مسار URL Checker فيرسل الرابط إلى الخدمات الخارجية، لكنه لا يستدعي redirect analyzer. لا توجد حماية وجهة واضحة في الطلب المباشر.

### 33. ما المعلومات التي قد تغادر الجهاز؟

URL كاملة في استعلامات خدمات السمعة، وقد تتضمن query parameters حساسة. مسار البريد يمكن أن يطلب الرابط نفسه مباشرة. التنبيهات المحلية قد تحتوي sender وsubject وURLs وflags؛ كما يرسل alert JSON إلى وجهة UDP المُعدة.

### 34. هل المشروع آمن للنشر العام؟

ليس كما هو. لا تظهر مصادقة أو صلاحيات أو rate limiting أو قيود egress، ومسار redirect يحتاج حماية، وبعض القيم غير الموثوقة تعرض عبر HTML مخصص مع escaping غير متسق. يلزم تقييم أمني وتغييرات مستقلة قبل النشر.

### 35. هل ملف pickle آمن؟

فقط إذا كان من مصدر موثوق. تحميل ملف pickle غير موثوق قد ينفذ شيفرة؛ لذلك لا ترفع أو تحمّل model من مصدر مجهول.

### 36. هل `Clean` يعني أن الرابط آمن؟

لا. قد ترجع مصادر خارجية `Unknown` مع score صفر، ويجمع النظام درجات المصادر حتى لو فشل بعضها. يجب فحص حالة كل مصدر وعدم اعتبار غياب نتيجة دليل سلامة.

## المقارنة والتطوير المستقبلي

### 37. لماذا لم يُستخدم حل بديل مثل قاعدة بيانات أو API منفصلة؟

لا توجد وثيقة قرار معماري تجيب عن ذلك. يمكن القول إن التنفيذ الحالي يركز على تطبيق Python بواجهة Streamlit وتخزين ملفات بسيط؛ أما تقييم SQLite أو REST service كبديل فيحتاج متطلبات استخدام وتوسع موثقة.

### 38. ما أهم تحسين أمني؟

أولوية عملية هي جعل الاتصالات الخارجية والـredirects صريحة وقابلة للتحكم، تقييد الوجهات والتحقق من TLS، وعدم إرسال روابط حساسة افتراضيًا. إضافة escaping موحد للمحتوى غير الموثوق ومصادقة/صلاحيات لازمة قبل التعرض لمستخدمين غير موثوقين.

### 39. ما أهم تحسين في دقة النتائج؟

فصل `Unknown` عن `Clean` عند تجميع المصادر، وتوثيق مصدر البيانات ونسخة النموذج وطريقة التقسيم، وتقييم مجموعة اختبار مستقلة. كما ينبغي مراجعة كيفية التعامل مع الحالات التي لا تحتوي على URLs.

### 40. هل هناك رخصة مفتوحة المصدر؟

لا يوجد ملف `LICENSE`. وصف المشروع بأنه تعليمي لا يحدد رخصة قانونية؛ يلزم قرار مالك المشروع وإضافة ملف رخصة مناسب قبل إعادة الاستخدام أو النشر.

### 41. هل كل المعلومات التاريخية للمشروع معروفة؟

لا. الكود والملفات لا توثق تاريخ اختيار المكتبات أو تحديات الفريق أو تجارب التشغيل السابقة بالتفصيل. يجب إضافة ما يعرفه الفريق بنفسه بدل اختراع قصة أو نتائج.
